
short polling vs long polling

polling is basically a consumer making continuous api calls to the queue for new messages

in short polling, the WaitTimeSecond is not specified
SQS only queries a subset of its servers which means that empty responses are going to be common because, we are not waiting for the server to receive new message and two the message may only exist in a specific SQS server at a given time
also with short polling you are essentially requesting the server again and again until you get a message in return. this burns up cost because of multiple request in short duration

in long polling, the WaitTimeSecond is specified between 1 and 20 seconds
SQS server polls all the available servers which means message miss is going to be rare
a single polling request is sent and within this single request the consumer polls for WaitTimeSecond period until it receives the message
if the consumer does not receive a message within that time frame then it has to repoll again
this saves money
