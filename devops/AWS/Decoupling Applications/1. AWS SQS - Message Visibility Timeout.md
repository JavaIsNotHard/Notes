

A mechanism by which SQS guarantees at-least-once delivery of messages. How??

The message visibility timeout is the duration in which the message is visible to different consumers.

once a consumer consumes message from a queue then SQS does not immediately delete the message, it makes the message invisible first. then it waits for the visibility timeout as well as for the consumer to call a DeleteMessage request to delete the message from SQS queue

if the consumer succeeds in deleting the message within the visibility timeout period then the message is permanently gone

if the consumer fails (consumer crashes, consumer takes long processing time) then the message becomes visible again and another consumer can pick up that event of message again

the default timeout is 30 seconds but we can change that by calling ChangeMessageVisibility in queue level

changing the message visibility timeout must be done properly because making it too long means the message will be retried by a different consumer after a longer time

Even if your handler finishes in 25 seconds, if the `DeleteMessage` call itself is delayed by network issues past the 30-second mark, the message reappears. which means our consumers must be idempotent such that retries of the same message do not cause many problems
